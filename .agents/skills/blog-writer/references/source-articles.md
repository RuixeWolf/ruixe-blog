# Source Articles

These author-written posts are the primary style references for this skill.

The skill should learn writing habits and editorial principles from them, not reproduce passages verbatim.

## Priority 1 — Primary voice anchor

### 我的个人博客网站的诞生

URL:
https://blog.ruixe.net/zh/posts/my-first-blog-website

Use it to learn:
- first-person motivation;
- long-form project narrative;
- requirements before implementation;
- technology-selection reasoning;
- alternative comparison;
- phase-based project history;
- direct personal opinions;
- light humor and asides;
- technical detail mixed with reflection;
- a legitimate reflective conclusion for a long project journey.

Do not copy its exact section structure into unrelated articles.

## Priority 2 — Workflow writing

### 我在 2026 年中旬的 AI Coding 工作流

URL:
https://blog.ruixe.net/zh/posts/ai-coding-workflow-2026-mid

Use it to learn:
- time-bounded workflow documentation;
- practical AI Coding terminology;
- reusable prompt blocks;
- procedural lists;
- how a general workflow can be followed by a real implementation case;
- distinguishing reusable practice from personal current preference.

## Priority 3 — Hands-on product experience

### 首次使用 VS Code Agents Window

URL:
https://blog.ruixe.net/zh/posts/vscode-agents-window-first-look

Use it to learn:
- chronological context for why a tool was retried;
- comparison against the author's previous workflow;
- discovering features during real use;
- recording limitations and unclear behavior;
- direct subjective evaluation;
- concrete task-based product testing.

## Priority 4 — Tutorial / knowledge-base writing

### 为网站服务器配置免费的 SSL 证书

URL:
https://blog.ruixe.net/zh/posts/nginx-certbot-https

Use it to learn:
- short personal opening;
- current-state and target-state framing;
- command-heavy tutorial structure;
- practical notes near the commands they explain;
- concise operational writing;
- occasional light humor without weakening technical clarity.

## Secondary references

Other Ruixe Blog posts may be consulted to understand newer terminology or project context, but they should not override the priority order above unless the user explicitly requests a newer style direction.

A later article can still provide:
- new technical vocabulary;
- updated project conventions;
- improved fact-checking habits;
- new article types.

Do not average all historical posts into one style profile.
